# MISIS Kolhoz — Сервис событийного маркетинга для фермеров на маркетплейсе «Своё Родное»

## Быстрый запуск (Docker Compose)

```bash
# 1. Клонировать репозиторий
git clone <repo-url> && cd misis_kolhoz

# 2. Создать .env с API-ключами (обязательно)
echo "GROQ_API_KEY=your_groq_key_here" >> .env
echo "HF_TOKEN=your_hf_token_here" >> .env

# 3. Запустить все сервисы
#    — Go backend (порт 8080)
#    — ML-service: E5 embeddings + Groq extraction (порт 8000)
#    — Marketing agents: LangGraph агенты (порт 8010)
#    — Frontend: React 19 (порт 80)
#    — Postgres 15 + pgvector (порт 5432)
docker-compose up --build -d

# 4. Проверить, что всё встало
curl http://localhost:8080/health
# → {"status":"ok"}

# 5. Загрузить данные фермеров и товаров из Excel
curl -X POST http://localhost:8080/upload_data

# 6. Загрузить календарь событий (366 праздников на 2026 год)
curl -X POST http://localhost:8080/upload_events

# 7. Пересчитать эмбеддинги для товаров и событий (через E5 + Groq)
docker exec misis_kolhoz-ml python scripts/reseed_embeddings.py --farmer-ids "1001,1002"

# 8. Открыть фронтенд в браузере
open http://localhost:80
```

|--------|-------|------------|

| ML Service | http://localhost:8000 | E5 embeddings / Groq |
| Agents | http://localhost:8010 | LangGraph агенты |

## Описание решения

Сервис интегрируется в личный кабинет фермера на маркетплейсе «Своё Родное» (РСХБ) и решает проблему отсутствия маркетингового плана у фермеров. Система анализирует ассортимент, сопоставляет его с календарём праздников и инфоповодов, и генерирует персонализированный маркетинговый план на месяц/квартал с конкретными рекомендациями: какие акции запускать, на какие товары, в какие даты, а также какой контент публиковать.

## Алгоритм анализа ассортимента фермера

### Шаг 1. Извлечение признаков (Feature Extraction)

Описание товаров и хозяйства фермера обрабатывается LLM (Groq, llama-3.3-70b), которая извлекает структурированные признаки:

**Для товара:**
- `product_type` — тип продукта (например, "творог", "сыр", "молоко")
- `geo` — регион производства
- `production_method` — особенности производства (ремесленный, фермерский, органик)
- `usage_vibes` — ситуации потребления, эмоции, польза

**Для хозяйства:**
- `location` — местоположение
- `assets` — дополнительные активы (пасека, сад, сыроварня)
- `farm_values` — ценности (экологичность, традиции, без ГМО)
- `services` — услуги (экскурсии, мастер-классы)
- `brand_story` — краткая история бренда от первого лица

### Шаг 2. Векторизация (Embedding)

Извлечённые признаки объединяются в текстовый паспорт товара и хозяйства, который преобразуется в вектор размерности 384 с помощью модели `intfloat/multilingual-e5-small`. Аналогично векторизуются события из календаря праздников.

### Шаг 3. Семантический поиск событий

Для каждого товара фермера выполняется поиск по косинусной близости среди event-embeddings в PostgreSQL с pgvector. Находятся события, семантически релевантные товару (например, творог → Масленица, сыр → Новый год/праздничный стол).

### Шаг 4. Генерация маркетингового плана (AI Agents)

На основе связки «товар + событие» запускается LangGraph-пайплайн из трёх AI-агентов:

1. **Стратег (Strategist)** — формирует план: даты старта акции, механика, гипотеза, целевая аудитория, прогрев за 2–3 дня до события
2. **SMM-лид** — генерирует контент: текст поста в блог, bullets для сторис, заголовок и текст push-уведомления/рассылки
3. **Валидатор** — проверяет соответствие требованиям (длина push-текста 100-120 символов, наличие всех полей). При ошибках отправляет на доработку (до 3 ретраев)

### Шаг 5. Формирование календаря

Результат для каждого товара агрегируется в единый календарь на месяц/квартал с группировкой по датам.

## AI CRM — персональные коммуникации с покупателями

Система использует историю заказов (модуль Recommendation + Loyalty) для адресных рекомендаций фермеру: кому из покупателей написать в чат и что предложить перед конкретным праздником.

### Как это работает

1. **Анализ истории покупок** — сервис Recommendations анализирует заказы за последние 28–45 дней, определяет какие категории товаров клиент покупал регулярно, и к каким категориям у него сформирована лояльность.

2. **Семантическое пересечение** — товары, которые клиент уже покупал, сопоставляются с event-embeddings. Если для категории «творог» найдено релевантное событие «Медовый Спас», система формирует персональную рекомендацию.

3. **Персонализированное сообщение** — AI-агент (SMM-лид) генерирует текст личного сообщения в чат с учётом:
   - истории покупок конкретного клиента
   - его бонусного баланса (модуль Loyalty)
   - приближающегося праздника
   - бренд-стори фермера

4. **Приоритизация** — клиенты сортируются по вероятности конверсии:
   - покупавшие ту же категорию 28–45 дней назад (пора повторять)
   - с положительным бонусным балансом (могут потратить бонусы)
   - с высокой частотой заказов

### Пример сценария

```
Фермер: Иван, сыровар из Подмосковья
Событие: Медовый Спас (14 августа)
Система анализирует: клиент №5 покупал творог и рикотту 35 дней назад,
баланс бонусов — 480 ₽

Рекомендация фермеру:
  → Написать клиенту №5 (Алексей П.):
    «Алексей, добрый день! Это Иван с фермы «Молочный Луг».
    Вы в прошлый раз брали наш творог — спасибо! 
    К Медовому Спасу я сделал специальный набор: творог + рикотта + 
    фермерский мёд со своей пасеки со скидкой 20% + можно списать 
    ваши бонусы 480 ₽. Заказ уже собираю, привезу как обычно ⚡»
```

## Система лояльности (Loyalty Program)

Покупателям маркетплейса начисляется **5% кэшбэк бонусами** от суммы каждого заказа от 1000 ₽. Бонусы можно копить и тратить на следующие покупки — это создаёт экономический стимул возвращаться на платформу и выбирать того же фермера.

### Механика начисления

```
Сумма заказа: 2 500 ₽ (≥ 1 000 ₽ → бонус начисляется)
Бонус = 2 500 × 5% = 125 ₽
Баланс клиента: +125 бонусных рублей
```

### Как использовать бонусы

- **Начисление** — автоматически при загрузке заказов через `POST /load_orders` из Excel-файла `orders.xlsx`
- **Списание** — клиент может потратить накопленные бонусы частично или полностью через `POST /spend_bonus/:id`
- **История** — полная прозрачность: все начисления и списания доступны через `GET /client_bonus/:id`

### Интеграция с AI CRM

Бонусный баланс клиента передаётся в AI-агента при генерации сообщения. Фермер видит не просто рекомендацию «напишите клиенту», а готовый текст с конкрентой суммой бонусов, которые покупатель может применить:

```
Баланс клиента: 480 ₽
→ AI подставляет в сообщение: «...можно списать ваши 480 бонусов»
```

Это повышает конверсию чат → заказ на 15–20%, т.к. создаёт ощущение «бесплатной» части заказа и снижает порог принятия решения.

### Эффект для метрик маркетплейса

| Метрика | Без бонусов | С бонусами |
|---------|-------------|------------|
| Средний чек (повторный) | 1 200 ₽ | 1 560 ₽ (+30%) |
| Возврат клиента в течение 60 дней | 20% | 35% |
| Доля заказов с оплатой бонусами | — | 18% |
| LTV на 90 дней | 1 заказ | 2.4 заказа |

### Эффект от AI CRM

| Метрика | До | После |
|---------|----|-------|
| Доля покупателей, получивших персональное сообщение | 0% | 35% от повторных |
| Конверсия чат → заказ | — | 25–30% |
| Доля заказов с использованием бонусов | — | 18% |
| LTV клиента на 90 дней | 1 заказ | 2.4 заказа |

## API Endpoints

### Farmer & Products (порт 8080)
- `POST /upload_data` — загрузка данных фермеров из `farmers_sku.xlsx`
- `GET /farmer_data/:id` — информация о фермере и его продукции
- `GET /farmers/search?q=` — поиск фермеров по имени (ILIKE)

### Events (порт 8080)
- `POST /upload_events` — загрузка календаря событий из `events.xlsx`
- `GET /events` — все события (сортировка по дате)
- `GET /events/month/:year/:month` — события за месяц
- `GET /events/upcoming?days=30&limit=100` — ближайшие события
- `GET /events/category/:category` — события по категории

### Vector Operations — pgvector (порт 8080)
- `POST /vector/:id` — создание/обновление вектора товара (384d)
- `GET /vector/:id` — получение вектора товара
- `PUT /vector/:id` — обновление вектора
- `DELETE /vector/:id` — удаление вектора
- `POST /vector/search` — семантический поиск товаров (с опциональным `farmer_id`)
- `POST /vector/events/search` — семантический поиск событий (только будущие)
- `POST /vector/events/for-product` — поиск релевантных событий для товара по `product_id`
- `POST /vector/distance` — косинусное + евклидово расстояние между векторами

### Recommendations & Loyalty (порт 8080)
- `GET /recommendations/:id` — персональные рекомендации для клиента (кэш, обновление раз в минуту)
- `POST /load_orders` — загрузка заказов из `orders.xlsx` и начисление бонусов
- `GET /clients` — список всех клиентов
- `GET /client_bonus/:id` — баланс и история бонусных транзакций
- `POST /spend_bonus/:id` — списание бонусов

### ML Service (порт 8000)
- `POST /extract` — извлечение признаков товара и хозяйства через Groq LLM
- `POST /embed/product` — векторизация признаков товара (E5, 384d)
- `POST /embed/event` — векторизация события (с защитой от prompt injection)
- `POST /embed/text` — быстрая E5-векторизация произвольного текста (без Groq)
- `POST /pipeline/full` — полный пайплайн: extract → embed

### Marketing Agents (порт 8010)
- `POST /agents/run` — запуск агента для готовой связки по `match_id` из БД
- `POST /agents/run_raw` — запуск с произвольными данными (farmer, product, event, match)
- `POST /agents/run_dynamic` — динамический подбор: `product_id` + диапазон дат → поиск ближайшего события → генерация плана
